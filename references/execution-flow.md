# 执行流程 — 三项核心能力

明确不做：安装、更新、卸载、配置发布、缓存重建、历史清洗及迁移的执行。

## 顺序

1. 用户问题与范围 → 翻译精炼 / 项目画像 / 技能插件推荐操作。
2. 发现客户端和实际路径；命令栏/侧边栏使用本次可见集合，不混入 catalog。
3. 首次全景采集内部证据；再次运行用同范围、30 天内且引擎指纹一致的基线做增量。
4. 已有工具评估 → 项目缺口 → 经授权的市场横向比较 → 建议执行。
5. 验证证据、来源、输出边界 → 首屏结论与行动 → 明细及深度分析入口。

## 可执行的分层扫描

`audit_skill_plugin_issues.py --scan-mode auto` 默认首次 full。
JSON 报告的 baseline 含时间、作用域、引擎及画像指纹、每项来源 SHA256 和发现。
`--baseline <previous-report.json>` 才复用；导出报告需明确请求，例如 `--json --output <new-report.json>`。
不自动保存基线；无基线时每次全景是正确降级，不能声称“已经增量”。

增量仍重新发现并指纹比对全部来源；只跳过未变化且无历史问题项的深度单项检查。关系与评分重新计算；旧问题重新验证，删除项单列。不是按 mtime 猜测。
生态模式中的 MCP 配置、Agent 和上下文证据每次重新读取；基线复用仅限 Skill 深度检查。

基线失效或超过 30 天自动退回 full 并说明原因。
增量时 critical≥1、warning/critical 合计≥5、资产变化≥25%、完整评分证据覆盖<75% 时，末尾建议并询问全景扫描。
这些阈值是可解释的产品默认值，不是市场研究结论；`--scan-mode full` 强制全景。

## 运行证据

`--signals-path` 明确输入使用证据；缺失、损坏或无归因记录时保留 unavailable。
调用次数必须有客户端、时间窗及采集覆盖；嵌套 exec 或隐式 skill 可能漏记，零记录不得证明未使用。
每次审查在内部模块中标记“已查/推断/估算/不可得”，实际启动及专业安全测试交给执行 Agent。

## 交付

按 report-template.md 输出；每项优化绑定来源与 action plan。完整扫描不等于全部可运行。
